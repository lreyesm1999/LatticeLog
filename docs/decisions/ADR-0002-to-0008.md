# ADR-0002 … ADR-0008 (local engine decisions)

## ADR-0002 — Event and context contract · accepted
A logical record independent of the binary encoding (`specs/event-model.md`). Attributes as an ordered list (keeps
order and duplicates). Context as chained immutable snapshots; the record stores only a reference to the innermost one
(own vs inherited provenance). Event identity = `(id, version)`; instance = the store's `sequence`.
Rejected alternatives: an attribute dictionary (loses order/duplicates) and copying the context into every record
(redundant).

## ADR-0003 — `.llog` format: little-endian, frames with a double CRC · accepted
Self-contained segments, blocks with a 24-byte header (header CRC + payload CRC), a footer with the index and a 20-byte
trailer. CRC-32 IEEE (the same as zlib) instead of CRC-32C, so any language can use its standard library. Hard limits
(64 MiB, expansion ratio ≤1100) against corruption and decompression bombs. Optional general-purpose compression =
raw DEFLATE (available in .NET and in Python's stdlib); Zstd/LZ4 are only evaluated as baselines.

## ADR-0004 — ACK semantics and journal · accepted
Three real levels (`AcceptedInMemory`, `WrittenToOs`, `FsyncConfirmed`) and three modes. A single writer per directory
(exclusive OS lock). A `MANIFEST.jsonl` journal with a CRC per line and an fsync per entry for transitions (sealing,
recovery, compaction). Torn byte tails are copied to `recovered/` and never interpreted.

## ADR-0005 — S/C/P criteria and fallback · accepted (provisional, to revisit with lab data)
Lattice-S and Lattice-C are part of format v0.1; DEFLATE compression is applied per block only when it reduces size
(automatic raw fallback). Lattice-P does not enter the format: the preliminary study with adaptive code lengths
(`reports/baseline-v1.md`) decides whether it is worth building. An explicit cost-based planner (`CodecPlanner`,
Fast/Balanced/Compact policies).

## ADR-0006 — Checkpoints and random access · accepted
Catalogs (schemas/contexts) are per segment and bounded; the footer lists every block, so decoding block k only needs
the earlier catalog blocks of that segment. Lattice-C resets its trace table on every block, so no block depends on
another record block.

**Update (format 0.2, 2026-11-18) — risk P04-R1 mitigated**: in 0.1 a corrupt catalog block invalidated the record
blocks that referenced it. Since 0.2 the footer stores a full (compressed) copy of the catalogs; the reader decodes
records with that copy and checks the catalog blocks against it. Catalog blocks are also DEFLATE-compressed when the
segment uses compression. Measured cost (`reports/baseline-v1.md` §6): ≤ 1.1 % on uncompressed variants and ≈ 0 % with
compression; on `inventory` (one context per operation) total size **drops** by 30 % because catalogs are now
compressed. Residual risk: unsealed (active) segments still depend on their catalog blocks until they are sealed.

**Update (P14, 2026-11-18) — open segments**: analyzed and bounded, with no format change. A crash cut cannot leave
records without their catalog, because every catalog block is written before the records that use it and a crash only
cuts the tail (test `Torn_tail_never_orphans_records_from_their_catalog`, cuts at every block boundary). Recovery seals
the segment and writes the footer copy. What remains is media corruption in a catalog block of a segment that is still
open (≤ 64 MiB / 1 h by default). Duplicating catalog blocks while the segment is open is not adopted: it would add
bytes proportional to the catalog weight (not measured) for a bounded risk. Reopened if real cases of corruption in
active segments appear.

## ADR-0007 — Own query language (DSL) instead of SQL · accepted
A minimal grammar of typed filters with no functions and no code execution (safe for MCP/server), with length/depth
limits. Full SQL is rejected for v1 (attack surface and unnecessary relational semantics). Aggregations through the API
(`stats`), not in the grammar.

## ADR-0008 — `event_ref` stable under compaction · accepted
`llog://<store_id>/e/<sequence>`. The sequence is global to the store, assigned by the writer and preserved by the
codecs, so compaction does not change references or cursors. Resolution uses the footer's sequence ranges. On the
server, references are resolved within the caller's authorized namespace (P17).

## ADR-0010 (shards/consistency), ADR-0012 (license/editions)
ADR-0010 is not written yet (it depends on P19). **ADR-0012, decided on 2026-11-18**: MIT license for the whole
repository (SDKs, format, engine, server and tools) and no commercial editions. The owner wants a free and open project,
like their other public projects. MIT is the simplest and best known, and it does not stop anyone from reading their
`.llog` data without LatticeLog.
